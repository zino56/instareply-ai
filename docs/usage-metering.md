# Usage metering — developer contract

Status: **not yet implemented**. This document defines the future backend contract for measuring customer usage. No billing, Stripe, or quota enforcement is in the product today.

## Product decision

- **Customer-facing billable unit:** one successful AI-generated outbound DM reply.
- **Customer-facing label:** `AI replies` (never "tokens", "credits", or "messages").
- **Internal cost telemetry:** LLM `input_tokens`, `output_tokens`, `model`, `estimated_cost`. Stored, never rendered to customers.

## What counts as one AI reply

Exactly **one** billable unit is recorded when **all** of the following are true:

1. The outbound message was generated by the AI (not typed by a human).
2. The outbound message was **confirmed sent** to Instagram (delivery accepted).
3. It is the first successful send for that `message_id` (retries do not double-count).

Explicitly **not** metered:
- Inbound DMs from customers.
- Manual/human replies.
- Drafts, previews, or generations that never send.
- Failed AI generations (model error, timeout, safety refusal).
- Failed sends (Instagram API error, rate limit).
- Retries that refer to an already-metered `message_id`.

## Event contract

Event name: `ai_reply_sent`

Emit once the outbound reply is confirmed sent.

| Field | Type | Visibility | Notes |
|---|---|---|---|
| `id` | UUID | internal | Idempotency key. Reject duplicates. |
| `client_id` | UUID | internal | Tenant identifier. |
| `conversation_id` | UUID | internal | |
| `message_id` | UUID | internal | Outbound message id. Second uniqueness key. |
| `occurred_at` | ISO-8601 UTC | internal | Time of confirmed send. |
| `unit_count` | integer | internal | Always `1` for a normal send. Corrections use negative values via a new event. |
| `ai_generated` | boolean | internal | Must be `true` for this event. |
| `delivery_status` | enum | internal | Must be `sent`. |
| `model` | string | internal | e.g. `gpt-4o-mini`. Never surfaced to customers. |
| `input_tokens` | integer | internal | LLM cost telemetry. Never surfaced. |
| `output_tokens` | integer | internal | LLM cost telemetry. Never surfaced. |
| `estimated_cost` | decimal (USD) | internal | LLM cost telemetry. Never surfaced. |

Idempotency: `(id)` unique, plus `(client_id, message_id)` unique for `delivery_status='sent'`. Producers may retry safely.

## Storage rules

- **Append-only.** Never edit or delete an event.
- **Corrections** are separate offsetting events with `unit_count = -1` and a reference to the original event id (`corrects_event_id`), producing an audit trail.
- Retention: keep raw events indefinitely (or per compliance policy). Aggregates are derived, not authoritative.

## Aggregation (future)

Monthly usage per client:

```sql
SELECT client_id,
       date_trunc('month', occurred_at) AS billing_month,
       SUM(unit_count) AS ai_replies_used
FROM usage_events
WHERE event = 'ai_reply_sent'
GROUP BY 1, 2;
```

Billing month boundary is the client's subscription anchor date (once subscriptions ship), not calendar month.

## Future safeguards (not built yet)

- **Soft warning** at 80% of the plan's monthly AI-reply allowance (in-app banner).
- **Hard limit** at 100%: pause AI auto-replies for that client until reset or upgrade. Inbound DMs still arrive; manual replies still work.
- **Per-client internal cost cap** (based on `estimated_cost`) as an abuse/runaway guard, independent of the customer-facing allowance.
- **Admin audit trail** of allowance overrides, manual credits, and corrections.

## Future API surface (draft)

- `GET /api/usage/current` → `{ ai_replies_used, ai_replies_limit | null, period_start, period_end }`
- `GET /api/subscription` → `{ plan_name, plan_status, ai_replies_limit, period_start, period_end, ... }`

Until these exist, the frontend renders `—` and "Usage tracking will be available soon." Never fabricate a quota, reset date, or usage count in production.

## Terminology — do / don't

| Do | Don't |
|---|---|
| AI replies | tokens |
| AI replies used | token usage |
| AI replies remaining | tokens remaining |
| Monthly AI reply allowance | monthly token quota |
| AI reply limit reached | out of credits |
| Your AI replies reset on {date} | your tokens refill on {date} |
